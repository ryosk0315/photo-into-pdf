# 写真 → PDF

iPhoneやスマホで撮った写真を、何枚でも1つのPDFにまとめてダウンロードするツール。

**写真は一切アップロードされません。** すべての処理がブラウザの中だけで完結します。
サーバーもアカウントも不要で、当然ながら無料、枚数制限もありません。

---

## 使い方

1. 写真を選ぶ（ドラッグ&ドロップ、貼り付け、カメラ撮影にも対応）
2. 並べ替える（サムネイルをドラッグ／ファイル名順・撮影日時順・逆順ボタン）
3. 必要なら重複をチェックして不要な写真を消す
4. 「PDFを作る」でダウンロード

### 設定

| 項目 | 選択肢 |
| --- | --- |
| **ページの形** | **A4に合わせる**（全ページA4統一・余白つき中央配置。横長写真はそのページだけ横向き。印刷や書類提出向き）／ **写真ぴったり**（写真の縦横比そのままのページ・余白なし） |
| **画質** | **軽さ優先**（長辺1400px）／ **標準**（長辺2200px・推奨）／ **高画質**（長辺3600px・ほぼ劣化なし） |
| **ファイル名** | 保存されるPDFの名前。空欄なら日時から自動生成 |

写真はEXIFの回転情報を読んで自動的に正しい向きになります。

iPhoneのHEIC形式にも対応しています。SafariはHEICを直接デコードできるため、
その場合は変換処理をスキップして高速に読み込みます（変換が必要なブラウザ向けに
`heic2any`もフォールバックとして同梱しています）。数十〜100枚以上のHEIC写真を
まとめて読み込む場合、この違いは体感できるほど大きくなります。

---

## 重複チェック

同じ写真や同じ書類が混ざっていないかを調べます。**見つけても勝手には消しません。**
「これとこれが似ています」と提示するだけで、消すかどうかは自分で決めます。

| 段階 | 何を見つけるか | ボタン |
| --- | --- | --- |
| **A. 完全一致** | バイト単位で同一の画像（同じ写真を2回選んだ等） | 「見た目でチェック」 |
| **B. 見た目の類似** | 同じ被写体の撮り直し。ずれ・明るさ・圧縮率の違いに強い | 「見た目でチェック」 |
| **C. 内容の一致** | **レイアウトが違っても書かれている文章が同じ書類** | 「内容でチェック（OCR）」 |

Cは端末内でOCR（文字認識）を実行し、読み取ったテキストの3-gram Jaccard類似度で判定します。
APIキーも課金も不要です。初回のみ日本語の学習データ（数十MB）をダウンロードします。

### 重要：書類は「見た目」では判定できません

**書類らしい画像（白い紙に文字）は、見た目のチェックの対象から意図的に外しています。**

実画像で測った結果です（数値は距離。小さいほど似ている）:

| 画像ペア | 16×16輝度MAE | インク分布 |
| --- | --- | --- |
| 同じ請求書の撮り直し（**本当の重複**） | 0.025 | 0.208 |
| 契約書 と 領収書（**全くの別物**） | 0.001 | 0.188 |
| 契約書 と 別内容の契約書（**別物**） | 0.001 | 0.030 |

本当の重複よりも、全くの別書類のほうが「似ている」と出ています。
縮小すればどの書類も「白地に細かい黒い点」になるため、これは閾値の調整では直りません。
知覚ハッシュ（dHash）、コントラスト正規化、インク密度プロファイルをそれぞれ16/24/32分割で
試しましたが、書類同士を分離できた指標はありませんでした。

そこで、彩度・明るい画素の割合・暗い画素の割合から画像が「書類」か「写真」かを判定し
（実測で彩度0.02 vs 0.56、白率0.99 vs 0.02と明確に分かれます）、書類は見た目の比較を行わず
OCRへ案内します。書類でも**完全一致の検出は行います**。

写真については見た目のチェックが有効に働きます（撮り直しペア0.049〜0.164 に対し、
無関係な写真同士は最小0.227）。

### OCRの限界

- **印刷された文字**は十分実用的です
- **手書き文字はほとんど読めません**。手書き解答のテストなどは、印刷された問題文の部分でしか判定できません
- 1枚あたり数秒かかります。100枚なら数分放置する想定です

## 公開する

### GitHub Pages（推奨）

1. このリポジトリの **Settings → Pages** を開く
2. **Source** を **GitHub Actions** にする
3. `main` に push すると `.github/workflows/pages.yml` が自動で公開します

公開後は `https://<ユーザー名>.github.io/photo-into-pdf/` で開けます。
iPhoneのSafariで開いて「ホーム画面に追加」すると、アプリのように使えます。

> URLを知っている人は誰でもアクセスできる状態になります（写真が共有されるわけではありません）。

### 単一HTMLファイルとして配る

```bash
npm run build     # → dist/photo-into-pdf.html
```

ライブラリを全部埋め込んだ1ファイル（約1.9MB）ができます。
これをLINEやAirDropで送れば、相手はダブルクリックで開くだけで使えます。
ネット接続も不要です（OCR機能を使うときだけ必要）。

## 中身

```
index.html              アプリ本体（HTML・CSS・JavaScriptを1ファイルに）
vendor/                 同梱ライブラリ（すべてMITライセンス）
  pdf-lib.min.js          PDF生成
  heic2any.min.js         HEIC → JPEG 変換
  sortable.min.js         ドラッグ並べ替え（タッチ対応）
build-standalone.mjs    vendor/ を埋め込んで単一HTMLを作る
test/                   実ブラウザでの検証（68項目）
```

OCRの `tesseract.js` だけはCDNから読み込みます（言語データが大きく、使うときだけ取得するため）。

ライブラリをCDNではなく同梱しているのは、オフラインでも動くようにするためと、
CDNが落ちても影響を受けないようにするためです。

## 開発

```bash
npm install
npx playwright install chromium
npm run serve     # http://127.0.0.1:8123
npm test          # 実ブラウザでの検証（test/README.md 参照）
```

## 動作環境

iOS Safari / Android Chrome / デスクトップの Chrome・Edge・Safari・Firefox。
ダークモードに対応しています。

写真の枚数に上限はありませんが、非常に多い場合は端末のメモリ次第です。
PDF生成は1枚ずつ処理してメモリを解放するようにしています。
